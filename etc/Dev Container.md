## 배경

프로젝트를 여러 개발자가 함께 개발할 때,

로컬 개발 환경 차이로 인해 다음과 같은 문제가 반복적으로 발생한다.

- OS 차이(macOS, Windows, Linux)
- Node.js 버전 불일치
- 패키지 매니저(npm, yarn, pnpm) 혼용
- “내 환경에서는 되는데” 문제

이러한 문제는 코드와 무관하며,

개발 생산성과 신뢰도를 지속적으로 저하시킨다.

---

## Dev Container란?

Dev Container는 **개발 환경을 Docker 컨테이너로 정의하고,
IDE(VS Code)와 연결하여 사용** 하는 방식으로 구현할 수 있다.


- 운영체제 환경
- Node.js 버전
- 패키지 매니저 및 버전
- 필수 개발 도구
- VS Code 확장 및 초기 실행 명령


VS Code는 다음 역할을 수행한다.

- 컨테이너 자동 빌드 및 실행
- 프로젝트 파일과 컨테이너 파일 시스템 연결
- 터미널, 디버거, 확장 프로그램 연동


즉, 개발 환경을 문서가 아니라 **코드로 관리하는 방식**이다.

---

## Dev Container의 핵심 개념

### 개발 환경의 기준 변경

기존 방식에서는 개발 환경의 기준이 각 개발자의 로컬 컴퓨터였다.

Dev Container를 사용하면 개발 환경의 기준이 다음과 같이 바뀐다.

- 기존: 개발자 로컬 환경
- 변경: 프로젝트에 포함된 컨테이너

로컬 환경은 중요하지 않으며,

컨테이너가 실제 개발 환경이 된다.

---

## Dev Container가 해결하는 문제

Dev Container는 다음과 같은 질문을 제거한다.

- Node.js를 설치해야 하는가?
- 어떤 버전의 Node.js를 사용해야 하는가?
- pnpm을 설치해야 하는가?
- OS가 달라서 문제가 생기지 않는가?

개발자는 환경 설정이 아니라 구현에만 집중할 수 있다. -> 개발 환경과 구현의 역할 및 책임 분리

---



## Dev Container 사용 흐름

Dev Container를 사용하는 프로젝트의 기본 흐름은 다음과 같다.

1. 프로젝트 저장소 clone
2. VS Code로 프로젝트 열기
3. Reopen in Container 선택
4. 자동 환경 구성 후 개발 시작

Node.js, 패키지 매니저, 의존성 설치를 위한 추가 작업은 필요하지 않다.

---

## Dev Container를 사용하는 이유

Dev Container를 사용하는 목적은 편의성이 아니라 **재현성과 일관성**이다.

- 환경 차이로 인한 오류 제거
- 신규 개발자 온보딩 비용 최소화
- 개발 환경과 CI 환경 간 차이 감소
- “내 환경에서는 된다” 문제 제거
