### ❓ Cloud Native란?

Cloud Native는 특정 기술(Docker, Kubernetes 등)을 **사용하는 것 자체**를 의미하지 않는다.

**클라우드 환경의 장점이 최대한 발휘되도록 처음부터 설계하는 방식**을 의미한다.

---

### ❌ 흔한 오해

- 클라우드에서 서비스하면 Cloud Native다
- Docker나 Kubernetes를 쓰면 Cloud Native다

→ **아님**

---

### ⭕ 정확한 이해

Cloud Native는 **기술 스택이 아니라 설계 철학**에 가깝다.

다음과 같은 질문에 “YES”가 나오도록 설계하는 것이 핵심이다.

- 트래픽 증가 시 자동으로 확장되는 구조인가?
- 서버 장애를 전제로 해도 서비스가 지속되는가?
- 배포와 변경이 잦아도 리스크가 낮은가?
- 운영이 사람 개입 없이 자동화되어 있는가?

- CNCF(Cloud Native Computing Foundation)
| **핵심 요소** | **의미** |
| --- | --- |
| **Microservices** | 거대한 서비스를 작게 쪼개어 독립적으로 배포 및 확장 가능하게 함. |
| **Containers** | 어떤 환경에서든 동일하게 실행되도록 애플리케이션을 패키징함. |
| **CI/CD** | 자동화된 테스트와 배포로 변경 리스크를 최소화함. |
| **DevOps** | 개발과 운영의 경계를 허물고 자동화된 운영 체계를 구축함. |

---

### 핵심 사고방식

- 온프레미스 관점: 서버는 귀하고 최대한 안 죽게 관리
- Cloud Native 관점: 서버는 소모품이며 언제든 교체 가능해야 함

---

### 프론트엔드 관점에서의 Cloud Native

- 특정 서버나 환경에 의존하지 않는 설정 구조
- 환경(dev/stage/prod) 변화에 유연한 구성
- 잦은 배포와 롤백을 전제로 한 설계
- API 변경에도 영향 범위를 최소화하는 구조
