## ❓ 접근성 트리란 무엇인가?

웹 브라우저가 HTML (DOM 트리)을 파싱하여 만드는 **또 다른 형태의 트리 구조**.
이 트리는 **스크린 리더(Screen Reader)**와 같은 **보조 기술(Assistive Technology)**이 웹 페이지의 콘텐츠를 이해하고 사용자에게 전달할 수 있도록 돕기 위해 설계되었습니다.

**간단한 비유:**
* **DOM 트리 (HTML):** 건물의 상세한 설계도 (모든 벽돌, 배관, 전선 정보까지 포함)
* **접근성 트리:** 건물의 안내 지도/팜플렛 (엘리베이터, 화장실, 안내 데스크 등 **핵심적인, 사용자가 이용할 정보**만 요약)

DOM 트리의 복잡한 시각적/구현적 요소들(CSS 클래스, `div`, `span` 등)을 제거하고, 요소의 **의미론적인 정보**만을 담고 있습니다.

## 🔑 접근성 트리의 핵심 구성 요소

모든 웹 요소는 접근성 트리에서 다음 4가지 핵심 정보로 표현됩니다:

1.  **Role (역할):** 이 요소가 무엇인가? (예: `button`, `link`, `heading`, `checkbox`, `textbox`)
    * `<button>` 태그는 자동으로 `role="button"`을 가집니다.
    * `<div role="button">`처럼 명시적으로 부여할 수도 있습니다.
2.  **Name (이름/레이블):** 이 요소를 뭐라고 불러야 하나? (예: 버튼 텍스트 "로그인", `<input>` 필드의 `<label>`)
    * `<button>로그인</button>` -> `name: "로그인"`
    * `<label for="id-input">아이디</label><input id="id-input">` -> `name: "아이디"`
    * `aria-label` 속성으로 명시할 수도 있습니다.
3.  **State (상태):** 지금 어떤 상태인가? (예: 체크박스가 `checked` 됨, 버튼이 `disabled` 됨, 입력창이 `focused` 됨)
4.  **Value (값):** 어떤 값이 들어있는가? (예: 텍스트 입력창에 입력된 실제 텍스트 값)

## ✨ 왜 Playwright 및 AI 에이전트(MCP)에게 중요한가?

### 1. Playwright 테스트 자동화 관점:

* **사용자 경험에 가까운 테스트:** `page.getByRole('button', { name: '로그인' })`과 같은 Playwright의 **접근성 기반 로케이터**는 사용자가 실제 "로그인 버튼"을 보고 클릭하는 방식과 동일하게 요소를 찾습니다.
* **테스트의 견고성 및 유지보수성 향상:**
    * CSS 클래스명이나 내부 `div`/`span` 구조가 변경되어도 테스트가 깨지지 않습니다.
    * 요소의 **의미(Semantic)**에 기반하여 찾기 때문에, HTML 구조 변경에 덜 민감합니다.
* **웹 접근성 개선 유도:** 접근성 기반 로케이터를 사용하려면 웹 페이지가 올바른 `role`, `name` (텍스트 콘텐츠, `aria-label`, `<label>` 등)을 가지고 있어야 합니다. 이는 개발 과정에서 자연스럽게 웹 접근성 표준 준수를 유도합니다.

### 2. AI 에이전트 (Playwright-MCP) 관점:

* **웹 페이지 이해의 핵심 도구:** AI 모델은 복잡한 HTML DOM 트리를 직접 파싱하기 어렵고 비효율적입니다.
* **의미론적 정보 제공:** 접근성 트리는 웹 페이지의 불필요한 시각적/구현적 노이즈를 제거하고, AI가 웹 요소의 **역할과 이름**을 정확하게 파악하여 **"무엇을 해야 할지"** 결정하는 데 가장 효율적인 정보를 제공합니다.
* **인간과 유사한 상호작용 가능:** AI가 접근성 트리를 통해 "이것은 '검색'이라는 이름의 '버튼'이다"라고 이해하면, 사람처럼 논리적으로 웹과 상호작용할 수 있습니다.

접근성 트리는 단순히 보조 기술만을 위한 것이 아니라, 웹 자동화 및 AI 에이전트가 웹 페이지를 **의미론적으로 이해하고 상호작용**할 수 있도록 하는 핵심적인 구조입니다. Playwright에서 `getByRole`과 같은 로케이터를 활용하는 것은 테스트의 안정성을 높이고, 궁극적으로 더 나은 웹 접근성을 가진 제품을 만드는 데 기여합니다.
